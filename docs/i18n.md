# Интернационализация

Три языка — сербский (латиница, корень домена), русский и английский
(подпапки `/ru/`, `/en/`); порядок важности локалей — sr, ru, en.
Всё, что связано с языками, живёт в четырёх местах `src/i18n/`:

| Файл               | Что там                                                                              |
| ------------------ | ------------------------------------------------------------------------------------ |
| `config.ts`        | список локалей (порядок важности), метаданные (`htmlLang`, `ogLocale`, Intl-форматы) |
| `routes.ts`        | реестр адресов: ключ страницы → английский слаг                                      |
| `pagemeta.ts`      | заголовки, описания и breadcrumb-имена страниц (`getPageHead`, `getPageMeta`)        |
| `ui/{sr,en,ru}.ts` | словари интерфейса; `satisfies UIStrings` не даёт разойтись составу ключей           |

Слаги английские на всех локалях — локаль живёт только в префиксе:
`/prices` ↔ `/ru/prices` ↔ `/en/prices`. Переводятся тексты, но не пути.
Страницы собираются динамическими маршрутами
(`src/pages/[...slug].astro`, `src/pages/[lang]/[...slug].astro`)
через общий `PageRoute`.

## Добавление страницы

1. Добавить ключ и английский слаг в `ROUTES` (`src/i18n/routes.ts`).
2. Описать состав блоков в `src/data/pages.ts` (реестр блоков).
3. Добавить заголовок/описание во все локали `src/i18n/pagemeta.ts` —
   это единый реестр метаданных: его же видит посетитель (`PageHero`)
   и его же отдают хлебные крошки JSON-LD.
4. Если страница входит в навигацию — добавить ключ в `NAV_KEYS`
   и подписи в `ui/*/ts`.

Адреса, canonical, hreflang и переключатель языка собираются из
`routes.ts` автоматически (`href`, `localeSwitchLinks`): руками в шаблонах
адреса не пишутся.

## Добавление локали

1. Запись в `LOCALE_META` (`config.ts`): `htmlLang`, `ogLocale`, Intl-форматы.
2. Словарь `src/i18n/ui/<locale>.ts` со всеми ключами
   (по образцу `ru.ts`, `satisfies UIStrings` подскажет пропуски).
3. Адреса субсетов шрифтов в `src/fonts/<family>.urls.ts`.

Слаги добавлять не нужно — они уже общие для всех языков.
Дальше `generatedRoutes()` само добавит страницы локали в сборку,
sitemap и переключатель языка.

## Переводы в клиентских скриптах

Клиентский JS не хардкодит тексты и не разбирает JSON: страница отдаёт
их атрибутами `data-msg-*`, скрипт читает значение у нужного элемента.

- формы: `data-msg-label`, `data-msg-error` на самих полях
  (`BookingForm.astro`);
- смена языка на лету: `data-msg-text`/`data-msg-link` с вариантами
  по локалям — `data-msg-title-sr/en/ru` (`404.astro`).

Правило: контент живёт в `src/i18n/ui/`, канал доставки — `data-msg-*`.
